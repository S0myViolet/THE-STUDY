# THE STUDY V2 — architecture and build conventions

V2 rebuilds the product around five functions — **LEARN, TRAIN, BUILD, PROVE, REVIEW** — with **TODAY** as
the front door. V1 (cases, observation games, salon, strategy, red thread) is preserved as an archive under
`/v1/*`; its cases are repositioned as transfer tests under PROVE. Nothing in V2 mastery is derived from V1 scores.

This document is the contract between the people (and agents) building V2. Read it before writing code.

## 1. Product model

- **TODAY** (`/today`): the plan for today, generated deterministically from learning state. "Why this plan?" is inspectable.
- **LEARN** (`/learn`): the curriculum — DOMAIN → COURSE → MODULE → CONCEPT — with interactive lessons (question → intuition → model → worked example → guided → independent → explain back → transfer → retrieval scheduled) and knowledge paths.
- **TRAIN** (`/train`): deliberate practice by real ability (skill areas), with a practice engine: question → attempt → confidence → submit → feedback → retry → solution → error classification → future review.
- **BUILD** (`/build`): investigations, models, essays, software, explanations, analyses, presentations. Structured projects with provenance-marked evidence.
- **PROVE** (`/prove`): no teaching, no hints, no AI. Exams (weekly / monthly / quarterly), unseen problems, cumulative retrieval, writing exams, oral explanations, transfer challenges (V1 cases), the baseline.
- **REVIEW** (`/review`): what is actually changing — progress, retention, knowledge, skills, exams, errors, projects, time, recommendations. Observations are rule-based over real evidence with minimum sample sizes; never fabricated.
- Secondary rooms: **Library** (`/library`), **Knowledge** (`/knowledge`), **Memory** (`/memory`), **Writing** (`/writing`), **Speaking** (`/speaking`), **Forecasts** (`/forecasts`), **Decisions** (`/decisions`), **Curator** (`/curator`), **Settings** (`/settings`), Search (⌘K).
- Entrance: `/enter` (V2 onboarding: enter → develop goals → interests → education → time → baseline → initial map → first 30 days). `?skip=1&name=X` creates a complete profile without the baseline (tests).

The learning loop for every concept: LEARN → UNDERSTAND → RETRIEVE → PRACTICE → APPLY → CREATE → TEST → REVISIT. Concept state
(`not_started … durable | fragile`) changes only on evidence, never on "Next".

## 2. KEEP / ADAPT / ARCHIVE

**Keep (as is)**: Next.js 16 app shell pattern, `StudyProvider`/`useStudy`/`useStudyQuery`, Dexie + Supabase adapters (`src/lib/persistence`), auth, design tokens and component classes (`globals.css`), `primitives.tsx`, icons, theme, AI provider layer (`src/lib/ai/provider.ts`, `client.ts`, `[op]/route.ts`), calibration maths (`src/lib/scoring/calibration.ts`), text metrics (`src/lib/scoring/text.ts`), Forecasts and Decisions rooms, Settings room (extended), scene engine (used by transfer cases), `tools/dev.sh`, flows, e2e harness.

**Adapt**: profile/preferences (V2 fields), command palette + search index (V2 entries), nav (V2 sections), onboarding (`/enter` is now V2), Curator (V2 tutor modes, Think First kept), memory scheduling (`src/lib/scoring/spaced.ts` lineage → `src/lib/v2/scheduler.ts`), estimate smoothing (`src/lib/scoring/estimates.ts` lineage → `src/lib/v2/mastery.ts`), cases (`CasePlayer` reused under `/prove/cases` as a transfer test with concept tagging), Investigations (→ Build projects), Archive entries (→ knowledge graph seed nodes), V1 knowledge questions (→ knowledge-breadth items), V1 memory items (→ importable retrieval items).

**Archive (under `/v1/*`, hidden from primary navigation, reachable from Settings → "V1 archive" and the palette)**: Desk, Casebook, Observation, Inference, Salon, Strategy, Memory (V1), Archive (V1), Rhetoric, Cabinet, Investigations (V1), Fieldwork, Red Thread, After Action, Profile, V1 Curator, V1 onboarding (`/v1/enter`). Route files are thin: `export default function Page({ params }) { const { slug } = use(params); return <XRoom slug={slug ?? []} /> }` (copy the pattern from an existing V1 route). Feature components are client components (`"use client"`) using `useStudy()` for `db`, `profile`, `prefs`.

## 4. Data model

- Content types: `src/lib/v2/content-types.ts`. Persisted entities: `src/lib/v2/types.ts`. Collections and local indexes: `src/lib/persistence/collections.ts` (V2 collections start at `concept_mastery`). Dexie version is 2.
- Profile: `UserProfile.v2?: ProfileV2` (goals, interests, educationLevel, dailyMinutes, onboardingComplete, baselineAttemptId, startedAt, v1ImportedAt). A user "needs V2 onboarding" when `!profile.v2?.onboardingComplete`.
- Preferences: V2 fields `planMode`, `customMinutes`, `lessonDepth`, `readingPace` (default 2 — every timed exposure is doubled) plus the V1 `thinkFirst`, `appearance`, `reducedMotion`.
- Cloud: `supabase/migrations/0002_v2.sql` adds the V2 tables (snake_case, jsonb for nested arrays/objects), `profiles.v2 jsonb`, and the new preference columns, with the same RLS loop as `0001_init.sql`. The row-mapping test parses every migration file.
- Evidence rules: every learning event writes through **one** of these write paths, never directly to `concept_mastery`:
  - `recordConceptEvidence` (mastery), `submitPractice` (practice → attempt + evidence + error + assistance), `reviewRetrieval` (memory), `finishExam` (exams), project completion (`kind: "project"`), reading recall (`kind: "recall"` / `application` when the reader applies a concept), applications (`kind: "application"`).
- Exam items are frozen into `ExamAttempt.form` **before** the learner answers. Model evaluation never mutates ground truth after seeing a response.

## 5. Engines (deterministic, `src/lib/v2/`)

All engines are pure where possible, with thin `db` wrappers. Unit tests live beside them in `__tests__/` and use `fake-indexeddb/auto` + `LocalDatabase` (see `src/lib/demo/__tests__/seed.test.ts` for the pattern).

## 6. AI (`src/lib/ai/`)

Server only (`ops.ts`, `provider.ts`); the browser calls `ai.call(op, input)` / `ai.stream(op, …)`. Every path has a deterministic fallback; the app is fully usable without a key. V2 ops (add to `OPS` with Zod outputs): `generateLesson`, `generatePracticeItem`, `evaluateSolution`, `evaluateWriting`, `evaluateExplanation`, `evaluateReconstruction` (reading recall), `generateTransferChallenge`, `generateExamItems`, `critiqueArgument`, `generateCounterargument`, `extractKnowledgeConcepts`, `recommendConceptLinks`, `createDailyPlanNarrative`, `analyzeLearningWeaknesses`, `generateProjectQuestions`, `tutorRespond` (streaming), `evaluateSpeaking`, `evaluateQuestion` (exists), `classifyErrorCategory`. Generated lessons/items are validated against the content schema and persisted in `generated_v2` before use. Exam items are never generated after the exam starts. Think First: `src/lib/curator/think-first.ts` stays the deterministic gate; the tutor distinguishes LOOKUP from REASONING.

## 7. Content (`src/content/v2/`)

- `skeleton.ts` fixes every domain/course/module/concept id. `curriculum/<domainId>.ts` exports `<DOMAIN_ID_UPPER>: DomainContent` (domain, courses, modules, concepts, lessons). Items: `items/<domainId>.ts` exports `ITEMS_<DOMAIN_ID_UPPER>: PracticeItem[]`. Others: `writing.ts`, `speaking.ts`, `questioning.ts`, `memory-techniques.ts`, `paths.ts`, `knowledge.ts`, `library.ts`, `projects.ts`, `exams.ts`, `passages.ts`, `first-month.ts`, `transfer.ts`. `index.ts` aggregates; `__tests__/validate.test.ts` checks every reference.
- Ids: concepts from the skeleton; items `it-<domain>-<nn>`; lessons `ls-<module>-<n>`; prompts `wp-<n>`, `sp-<n>`, `qe-<n>`; paths `path-<slug>`; nodes kebab-case; sources `src-<slug>`; projects `pt-<slug>`; passages `pas-<slug>`.
- No lorem ipsum, no placeholders. Accurate, checkable content; where a figure is contested, say so. British or American spelling consistently within a file. Numeric items must have unambiguous answers with a tolerance.

## 8. UI conventions

- Use the existing primitives (`Button`, `PageHeader`, `Field`, `TextArea`, `Segmented`, `Choice`, `ConfidenceDial`, `Countdown`, `HairlineProgress`, `Dialog`, `Empty`, `Note`, `Stat`, `Kbd`, `useCountdown`, `useStopwatch`) and classes (`.page`, `.sheet`, `.sheet-raised`, `.eyebrow`, `.serif`, `.display`, `.numeral`, `.prose-study`, `.btn*`, `.field`, `.segmented`, `.nav-item`, `.rule`). Tokens: paper/ink/line/wine/forest/brass/ok/warn/bad. No purple, no gradients, no emoji, no confetti, no XP.
- Atmosphere per section: Today = desk agenda; Learn = annotated textbook (serif reading column, marginal notes); Train = focused workspace (one problem, generous whitespace, mono numerals); Build = research studio (columns, sources, claims); Prove = sparse and examination-like (`ExamShell` hides navigation, shows a quiet timer); Review = analytical (tables, small multiples, plain numbers with n).
- Every screen works at 390 px wide. Wide tables scroll inside `overflow-x-auto`.
- Copy: precise, calm, no exclamation marks, no "Great job". Feedback names the exact passage or step.
- Model-assisted paths show a one-line notice when the model is unavailable and fall back deterministically. Never fake analytics; when n is too small, say so.

## 9. Working rules for builders

- Own your files. Shared files you may **not** edit without coordinating: `src/lib/v2/types.ts`, `src/lib/v2/content-types.ts`, `src/content/v2/skeleton.ts`, `src/content/v2/index.ts`, `src/lib/persistence/collections.ts`, `src/lib/nav.ts`, `globals.css` (additive utility classes are fine at the end of the file), `src/lib/ai/schemas.ts` and `ops.ts` (only the AI agent). If you need a change there, put it in your report.
- Run `npx tsc --noEmit` before finishing; it must pass for the whole repo. Run your own tests with `npx vitest run <path>`. `npm run lint` must stay clean for your files.
- The dev server: `bash tools/dev.sh` (port 3000, idempotent; if you must restart: `pkill -f "next dev"; bash tools/dev.sh`). Verify UI with a Playwright flow under `tools/flows/v2-<name>.mjs` (pattern: `tools/flows/case-lookback.mjs`) and screenshots via `node tools/shot.mjs <route> <out.png>` when helpful. Do not leave flows failing.
- No model identifiers in code, comments, commits or copy. No API keys anywhere. Keep V1 code compiling.
